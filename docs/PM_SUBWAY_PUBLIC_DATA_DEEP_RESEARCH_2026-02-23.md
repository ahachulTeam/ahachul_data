# 지하철 공공데이터 딥서치 리포트 (PM)

- 작성일: 2026-02-23
- 목적: 외국인 친화형 지하철 정보 서비스 기획을 위해, 공공데이터 기반 API 인벤토리와 콘텐츠 확장 가능성을 정리
- 범위: 서울/수도권 지하철 중심, 공공데이터 + 필수 보완 데이터(지도/로컬검색)

## 1) 결론 요약
1. **즉시 구현 가능한 핵심 경험**
- 가까운 역 추천(도보 시간 포함), 첫차/막차, 실시간 도착, 환승 동선, 역사 편의시설, 주변 간단 식사처
2. **데이터 전략**
- 실시간/운행 데이터는 공공데이터를 우선 사용
- 도보 시간/주변 가게는 지도/로컬 검색 API를 보완 결합
3. **외국인 대상 핵심 포인트**
- 다국어(영/중/일) 역명/출구/환승 안내
- “지금 출발하면 몇 분 뒤 탑승 가능한지” 중심의 행동형 UX
- 결제/운임/막차 리스크를 사전에 경고

## 2) 공공데이터 API 인벤토리 (1차)

### A. 서울교통공사/서울시 계열
1. 서울교통공사_지하철노선별지하철역정보
- 용도: 역 메타/노선/운영 기본정보
- 링크: https://www.data.go.kr/data/15058404/openapi.do
2. 서울교통공사_빠른하차정보
- 용도: 환승/출구 기준 빠른 하차칸 추천
- 링크: https://www.data.go.kr/data/15143840/openapi.do
3. 서울교통공사_최단경로이동정보
- 용도: 역사 내부 이동 동선/최단 이동
- 링크: https://www.data.go.kr/data/15143842/openapi.do
4. 서울교통공사_지하철알림정보
- 용도: 운행 이슈/공지/지연 알림 연계
- 링크: https://www.data.go.kr/data/15144070/openapi.do
5. 서울 열린데이터광장_실시간 지하철 도착정보
- 용도: 역 단위 실시간 도착/행선/상하행
- 링크: https://data.seoul.go.kr/dataList/OA-12764/S/1/datasetView.do

### B. 국토교통부/국가교통 계열
1. 국토교통부_도시철도 노선정보
- 용도: 전국 노선 확장 시 표준 메타
- 링크: https://www.data.go.kr/data/15142033/openapi.do
2. 국토교통부_도시철도노선별경유역정보
- 용도: 노선-역 그래프 구성
- 링크: https://www.data.go.kr/data/15142034/openapi.do
3. 국토교통부_고속시외버스/도시철도 이용자 OD (연계)
- 용도: 혼잡 예측/수요 분석(기획/분석용)
- 링크: https://www.data.go.kr/data/15142072/openapi.do

## 3) 외국인 친화 콘텐츠로 확장 가능한 항목

### 3-1. “내 집에서 안암역까지 몇 분?”
- 필요 데이터
1. 사용자 출발 좌표(또는 주소)
2. 역 좌표(공공데이터)
3. 보행 경로/시간(지도 라우팅 API)
- 출력 포맷 예시
- `도보 11분(850m), 경사 완만, 횡단보도 2회`

### 3-2. 첫차/막차 + 막차 리스크
- 필요 데이터
1. 역/노선별 시간표(공공데이터)
2. 실시간 도착정보
3. 현재 시각/요일/공휴일 여부
- 콘텐츠 예시
- `오늘 안암역 하행 막차까지 27분 남음`
- `지금 출발하면 막차 탑승 위험(도보 15분 + 대기 20분)`

### 3-3. 역사 주변 요깃거리(간단 식사)
- 필요 데이터
1. 식품위생 인허가/업종 데이터(공공데이터)
2. 지도/로컬검색 API(운영시간/리뷰/거리)
- 콘텐츠 예시
- `출구 3 기준 5분 내: 김밥/샌드위치/카페`
- `영문 메뉴 가능 여부`

### 3-4. 환승/출구/빠른하차 추천
- 필요 데이터
1. 빠른하차정보 API
2. 역사 내부 최단경로 이동정보 API
- 콘텐츠 예시
- `성수행 5-2칸 탑승 시 출구 3까지 2분 단축`

### 3-5. 안전/운행 이슈 알림
- 필요 데이터
1. 지하철 알림정보 API
2. 실시간 도착 stale/confidence 지표
- 콘텐츠 예시
- `현재 정보 지연(LOW): 최신 수신 3분 전`

## 4) 딥서치 운영 방식 (계속 업데이트 가능하게)

### 4-1. 수집 파이프라인
1. 데이터 소스 카탈로그 테이블 유지
- 필드: `기관`, `API명`, `인증방식`, `호출제한`, `갱신주기`, `비고`, `링크`
2. 주간 점검 항목
- 응답 스키마 변경 여부
- 호출 제한/인증키 정책 변경 여부
- 장애/지연 빈도

### 4-2. 평가 스코어링
- `제품가치`(외국인 사용성)
- `데이터신뢰도`(갱신주기/결측률)
- `구현난이도`(인증/정규화/비용)
- `운영비용`(호출량/캐시 필요성)

### 4-3. 우선순위 백로그
1. 실시간 도착 + confidence 배지
2. 첫차/막차 + 도보 시간 결합
3. 빠른하차 + 출구 중심 추천
4. 주변 간단 식사/편의시설 추천

## 5) 팀 액션 아이템
1. FE
- 신뢰도 배지/지연 문구 다국어 표준화
2. BE/Infra
- 실시간 v2 캐시/stale/품질지표 완성
3. PM
- 외국인 핵심 시나리오(출근/귀가/야간) 3종 UX 스크립트 확정
4. QA
- 다국어 문구/시간대/막차 경계 케이스 회귀 시나리오 추가

## 6) 비고

- 운영 전 최종 점검은 각 API의 공식 문서 최신본을 기준으로 재검증 필요
